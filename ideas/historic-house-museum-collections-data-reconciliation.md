# Historic House Museum Collections Data Reconciliation

## Problem statement

Small historic house museums and heritage sites (NAICS 712120) run their permanent
collection through PastPerfect, a desktop/cloud collections-management package, but
day-to-day inventory and condition work is generated by volunteers and interns who
work in Excel and Word rather than in PastPerfect directly. A paid staff role — often
part-time — exists specifically to take that offline work and key it into the
authoritative database, then reconcile it against existing catalog and location
records so the two do not drift apart. Employers are advertising for this as a named,
recurring duty rather than an occasional cleanup task.

## Automation hypothesis

SPECULATIVE. A structured intake form or lightweight mobile app for volunteers and
interns that writes directly into PastPerfect's schema (or a staging table validated
against it) could remove the hand-merge step, provided PastPerfect's import format
and field structure can be reverse-engineered or accessed via its reporting/export
tools — PastPerfect does not publish a public API, so the integration surface would
likely have to be a file-format bridge (CSV/XML matching PastPerfect's import
templates) rather than a live API connection. This would need validating against
PastPerfect's actual import capabilities before being treated as tractable.
